# PLAN v0.9 — 오늘의 뉴스 티커 (DAON)

> 작성: 2026-11-01 | 플랫폼: android (Fire HD 10, API 28) | 상태: **설계 확정 · 구현 전**
> 목업: `docs/mockups/v0.9-news/` (index.html + screens/6장)

## 1. 목표

달력 화면 **상단 가운데 빈 곳**에 최신 뉴스 제목을 느리게 흘려 보낸다.
키오스크를 벗어나지 않고, 누르면 오늘의 뉴스 목록 → 기사 본문까지 읽는다.
인터넷이 끊겨도 앱이 멈추거나 경고로 시끄러워지지 않는다.

- 하루 종일 켜 두는 벽시계이므로 **조용하고 느리게**, 70대 사용자가 읽을 수 있는 크기.
- 뉴스는 **연합뉴스 최신기사 RSS + SBS 사회 RSS** 두 곳에서 받는다(키·계정 불필요).
- 기사 원문은 **앱 안에서 글자만** 뽑아 보여 준다. 브라우저·다른 앱을 열지 않는다(키오스크 유지).

## 2. 확정한 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 위치 | 달력 상단 바, 날짜와 `라디오/TV/설정` 사이 (`weight(1f)`) | 사용자가 지목한 빈 곳. 달력 높이를 줄이지 않는다 |
| 크기 | 시각 높이 43dp(버튼과 동일), **터치 영역 48dp**, 글자 18sp | 기존 상단 바 리듬 유지 + 최소 터치 크기 |
| 움직임 | 왼쪽으로 **45px/s**(30dp/s), 제목 간격 76px, 좌우 페이드 | "천천히". 27px 글자가 1초에 45px 이동 |
| 갱신 | 기본 **1시간**, 설정에서 30분/1시간/3시간/6시간 + `지금 갱신` | 사용자 결정. 두 피드 합계 281KB/회 → 하루 약 6.7MB |
| 클릭 | **뉴스 목록(최신 20건)** → 기사 본문 | 흐르는 제목을 정확히 집을 수 없어 오탭을 없앤다 |
| 출처 | **연합뉴스 + SBS** (한 목록에 섞어 최신순) | 사용자 결정. 한 곳이 죽어도 다른 곳은 계속 보인다 |
| 목록 구성 | 출처별 **최대 10건씩 = 20건** (한쪽이 비면 다른 쪽으로 채움) | 한 통신사가 목록을 독차지하지 않게 |
| 본문 | HTTP로 기사 페이지를 받아 추출, 실패하면 RSS 요약 | WebView·브라우저 없이 앱 안에서 해결 |
| 저장 | prefs JSON(출처별 30건) + 출처별 마지막 성공 시각 | 재시작·오프라인에서도 마지막 소식 유지 |
| 유지 | **48시간** 지난 기사는 표시·저장에서 제외. 성공 시 즉시 교체, 실패 시 캐시 유지 | 아래 §3-3 |
| 범위 | **달력 화면에서만** 표시 | 다른 화면에는 상단 바가 없다. 자동 전환과 충돌 없음 |
| 실패 | 라벨을 흐리게 + 마지막 시각. 받은 소식이 0건일 때만 "다시 시도" | 벽에 붙은 기기가 빨간 오류로 시끄러우면 안 된다 |

## 3. 데이터

### 3-1. 출처 — 실측 검증 (2026-11-01)

| 후보 | 응답 | 루트 인증서 | 대상 기기 신뢰 저장소 | 판정 |
|---|---|---|---|---|
| **연합뉴스 최신기사** `www.yna.co.kr/rss/news.xml` | 200 · 94KB · 120건 · 17:53까지 | DigiCert Global Root G2 | **있음**(`c90bc37d.0`) | **채택** |
| **SBS 사회** `news.sbs.co.kr/news/SectionRssFeed.do?sectionId=03` | 200 · 187KB · 29건 | Amazon Root CA 1 | **있음**(`fd08c599.0`) | **채택** |
| SBS 전체 속보 `newsflashRssFeed.do` | 200 · **776KB** · 101건 | Amazon Root CA 1 | 있음 | 제외 — 매시간 776KB는 과함 |
| Google News RSS | 200 · 100KB | GTS Root R4 | **없음**(`5acf816d.0` 없음) | **제외** — HTTPS 실패 |
| JTBC 속보 | 200 · 10KB · **1건**, 2024-10-29 정지 | DigiCert Global Root G2 | 있음 | 제외 |
| MBC RSS | 301 → HTML | — | — | 제외(피드 아님) |
| 한겨레 RSS | 200 | USERTrust RSA(교차 서명) | 있음 | 예비 |

- Fire OS 7.3.1.2(보안 패치 2018-10-05)는 시스템 CA **137개**만 신뢰한다.
  TBS FM 이 실패한 것과 같은 이유로 **Google News RSS 는 이 기기에서 쓸 수 없다**.
- SBS 섹션 피드는 `sectionId` 를 바꿔도 29건씩만 준다. `newsflash`·`sitemap` 은 섹션 인자를 무시하고 776KB 전체를 준다.
  → 시간당 부담을 줄이려고 **사회(sectionId=03)** 한 섹션만 쓴다.
  정치·경제·국제를 함께 받으면 236KB×4 = 944KB/회가 되어 채택하지 않는다.
- 두 피드 모두 `title` + `description`(1~2문장) + `link` + `pubDate`(RFC-822)를 준다.
  연합뉴스에는 스포츠 전적·순위 기사도 섞이므로 정리 규칙이 필요하다.

### 3-2. 정리 규칙
- 제목이 `[여자농구 청주전적]`, `[프로배구 전적]`, `[KPGA 최종순위]`, `[북한단신]`, `[자막뉴스]` 같은
  **전적·순위·단신·자막**이면 뺀다.
- 끝의 `(종합)`, `(종합2보)`, `(1보)` 를 떼어 같은 사건 중복을 합친다.
- 같은 제목이 두 출처에 있으면 **먼저 온 쪽(최신 발행 시각)** 하나만 남긴다.
- 제목 12자 미만(전적류 잔여)은 뺀다.
- 목록은 출처별 최대 10건씩 합쳐 **최신 20건**. 한쪽에 10건이 없으면 다른 쪽으로 채운다.

### 3-3. 유지 기간 — 어떻게 동작하나

| 상황 | 동작 |
|---|---|
| 새 목록을 받음 | **그 출처 몫을 즉시 교체한다.** 피드에서 빠진 기사는 목록·티커에서 바로 사라진다 |
| 한 출처만 실패 | 성공한 출처만 교체하고, 실패한 출처는 **마지막 성공 목록을 그대로 유지** |
| 둘 다 실패 | 아무것도 지우지 않는다. 화면은 마지막 소식 + 마지막 시각 |
| 기사가 48시간 지남 | 표시에서 빠지고, 다음 저장 때 파일에서도 지운다 |
| 앱 재시작 | prefs 에서 읽어 즉시 표시(최대 48시간 이내 것만) |
| 기사 본문 | **저장하지 않는다.** 열 때마다 1회 받고, 패널을 닫으면 버린다 |

- "하루 지나면 폐기"가 아니라 **48시간**이다. 밤사이 갱신이 한두 번 실패해도 아침에 빈 화면이 되지 않게 하려는 여유다.
- 저장 상한은 출처별 **30건**. 표시는 20건이므로, 잠깐 갱신이 밀려도 목록이 비지 않는다.
- 즉시 교체이므로 **"갱신 = 이전 것 폐기"가 맞다**. 단, 실패했을 때는 폐기하지 않는다.
- 저장 용량: 30건×2곳 ≈ JSON 25~35KB. SharedPreferences 한 키로 충분하다.

### 3-4. 기사 본문 추출
- **연합뉴스** `https://www.yna.co.kr/view/...`
  `<article id="articleWrap">` 안 `story-news article` 블록에서 **`<figure>` 를 먼저 제거**하고
  남은 `<p>` 를 순서대로 모은다(사진 설명·기자 프로필 제외). 실측 문단 17개.
- **SBS** `https://news.sbs.co.kr/news/endPage.do?news_id=...`
  `<script type="application/ld+json">` 의 `@graph[0].articleBody` 를 쓴다. 실측 전문 955자 확인.
  JSON-LD 가 없으면 `<p>` 수집으로 대체.
- `articleBody` 는 한 덩어리라 문단이 없다. **문장 끝(`다.` `요.` `까?` `죠.`) 뒤 공백에서 끊어** 문단으로 나눈다(6~12문단).
- 사진 설명 줄(`▲ …`, `(사진=…)`)은 뺀다. 연합뉴스의 `<figure>` 제거와 같은 목적이다.
- 태그 제거 + 엔티티 복원(`&apos;` `&quot;` `&amp;` `&#39;` `&nbsp;` `&#9650;`) + 공백 정리.
- 두 곳 모두 실패하면 RSS `description` 으로 대체(오류 표시 없음).
- 외부 도메인 링크는 요청하지 않고 RSS 요약만 보여 준다.

### 3-5. 표시 규칙
- 시각은 오늘이면 `17:53`, 어제면 `어제 17:53`, 그 이전이면 `10/31 17:53`(자정을 넘겨도 헷갈리지 않게).
- 목록 행과 기사 상단에 출처를 항상 붙인다: `연합뉴스` / `SBS`.
- 원문 주소는 저장만 하고 화면에는 걸지 않는다(키오스크 유지).

### 3-6. 화면 구조 변경점
- 현재 `HomeTopBar` 는 날짜 `Column` 이 `weight(1f)` 로 남는 폭을 먹는다. 이를 **날짜 `wrapContentWidth`** 로 바꾸고
  **티커가 `weight(1f)`** 를 갖게 한다. 오른쪽(오늘 일정 알약 · 라디오 알약 · 화면 점 · 버튼)은 지금 순서 그대로.
- 날짜·음력 줄은 `maxLines = 1` + 필요 시 `TextOverflow.Ellipsis`. 115% 글씨에서도 한 줄 유지(현재도 1줄).
- 티커 폭이 420px 미만이면(오늘 일정 + 라디오 알약이 함께 있을 때) 티커를 그리지 않고 기존 배치로 돌아간다.

## 4. 화면 설계 (1920×1200, 1dp=1.5px)

### 티커 (달력 상단 바)
```
[ 2026년 11월 1일 일요일 ]   [• 뉴스 │ 울산 폐기물처리업체 화재 진압 중… ]   [• • • • •] [라디오] [TV] [설정]
    음력 9월 22일 · 상강 …
```
- 높이 43dp(64.5px), radius 12dp, 배경 surface, 테두리 rule 1px.
- 왼쪽 라벨 `뉴스` 15sp Bold accent + 9px 점 + 1px 세로선.
- 본문 18sp Medium `textPrimary`. 제목 사이 76px, 구분점 없음. 두 출처를 섞어 최신순으로 흘린다.
- 좌우 페이드 34/60px. 남는 폭 700~840px, **420px 아래면 티커를 숨긴다**(오늘 일정 알약·라디오 알약이 둘 다 있을 때).
- 115% 글씨: 18sp→20.7sp(31px), 줄 높이 41px → 43dp(64.5px) 안에 들어간다.
- 터치 영역은 48dp로 잡고 시각만 43dp.

### 뉴스 목록 (오른쪽 600dp 패널)
- 달력 위에 `scrim` + 오른쪽에서 600dp(900px) 패널. 날짜 상세(520dp)·설정(680dp)과 같은 방식.
- 제목 `오늘의 뉴스`, 부제 `연합뉴스 · SBS · 18:02 갱신 · 20건`.
- 행: 시각 23px(78px 열) + 출처 칩(`연합뉴스`/`SBS`) + 제목 28px 2줄 + `›`. 새 소식 3건은 시각을 accent 로.
- 아래 안내: `제목을 누르면 기사 본문이 열립니다`.

### 기사 (같은 패널, 두 번째 상태)
- 위: `‹ 목록` + `✕`, `SBS · 17:50 · 사회`.
- 제목 52px 3줄까지, 본문 27px/1.66(≈18sp/27sp와 같은 비율).
- 아래: `‹ 이전 기사` · `3 / 20` · `다음 기사 ›`.
- 스크롤은 본문만. 아래 70px 페이드.
- 원문 링크·브라우저 버튼 없음. 출처는 상단 메타에만.

### 설정 → 뉴스
- `뉴스 티커 표시` 켬/끔(기본 켬).
- `새로 고침 간격` 30분·**1시간**·3시간·6시간.
- `지금 갱신` + `마지막 17:53 · 연합뉴스 10 · SBS 10`.
- 안내: `출처: 연합뉴스 최신기사 · SBS 사회 RSS. 인터넷이 끊기면 마지막 소식을 보여 주고, 다시 연결되면 스스로 갱신합니다.`

## 5. 기술 설계

### 파일
| 파일 | 역할 |
|---|---|
| `data/news/NewsSource.kt` | `YONHAP`, `SBS` — 이름·피드 주소·본문 추출 방식 |
| `data/news/NewsItem.kt` | `source, title, link, summary, publishedAt` |
| `data/news/NewsFeedParser.kt` | RSS 2.0 파싱(`XmlPullParser`), 정리·중복 제거, 출처 합치기 |
| `data/news/NewsRepository.kt` | HTTP(타임아웃 8/12s), 두 피드 병렬 요청, 캐시 저장 |
| `data/news/ArticleExtractor.kt` | 연합뉴스 `figure` 제거 → `<p>`, SBS JSON-LD `articleBody` |
| `ui/NewsTicker.kt` | 마퀴(30fps 상한), 페이드, 상태(정상/오프라인/없음) |
| `ui/NewsPanel.kt` | 목록·기사 두 상태, 스크롤, 이전/다음 |
| `ui/SettingsPanel.kt` | `뉴스` 섹션 추가 |
| `ui/DashboardViewModel.kt` | 주기 갱신, 백오프, 패널 상태, `paused` 조건에 추가 |
| `core/AppPrefs.kt` | `news_enabled`, `news_interval_min`, `news_items`, `news_updated_at`(출처별) |

- 의존성 추가 없음: `HttpURLConnection` + `XmlPullParser` + 정규식. Jsoup/WebView 사용 안 함.
- 파싱은 `Dispatchers.IO`, 티커 상태 갱신만 메인. 두 피드는 **병렬**로 받는다(직렬이면 2배 대기).
- 첫 프레임 뒤 시작(T-042 방식). 콜드 스타트 예산에 영향 없게.

### 갱신·백오프
```
앱 시작(첫 프레임 뒤) → 캐시 즉시 표시 → 네트워크 갱신(두 피드 병렬)
성공: interval(기본 1시간) 뒤 다음
실패: 5분 → 15분 → 1시간 (연속 실패 횟수로)
성공하면 실패 횟수 0
```
- `설정 → 지금 갱신` 은 실패 횟수를 무시하고 즉시 1회.
- 출처별로 성공/실패를 따로 기록한다. SBS 만 실패하면 연합뉴스 몫만 새로 교체한다.
- 앱이 백그라운드(`ON_STOP`)면 갱신하지 않는다. `ON_RESUME` 에서 간격이 지났으면 1회.

### 오류 코드
- `E-AND-NEWS-0001` 피드 요청·응답 실패(출처 이름 포함)
- `E-AND-NEWS-0002` 기사 본문 요청 실패(사용자에게 오류로 보이지 않음, 요약으로 대체)
- `E-AND-NEWS-0003` 피드 형식 오류(파싱 0건)
- 로그에는 출처·URL·건수만. 기사 본문은 남기지 않는다.

### 티커 애니메이션
- `withFrameNanos` 누적 오프셋, **33ms 이상일 때만** 이동(30fps 상한).
- `Modifier.graphicsLayer { translationX = -offset }` 로 리컴포지션 없이 이동.
- 정지 조건: `화면 != CALENDAR || 뉴스 패널 열림 || 설정 열림 || 날짜 상세 열림 || lifecycled != RESUMED || 티커 폭 < 420px`.
- 제목이 바뀌면(새 갱신) 오프셋을 0으로 되돌리고 다시 시작.
- 30fps 상한 근거: 상시 켜짐 기기의 발열·배터리. 기존 "달력 유휴 0프레임" 지표는
  **"달력 유휴 30fps(티커)"** 로 바뀐다 → T-043 문서에 명시한다. 필요하면 15fps 로 낮출 수 있게 상수화.

### 자동 전환
- `paused` 조건에 `newsPanelOpen` 추가. 목록·기사·로딩 중 모두 정지.
- 패널을 닫으면 남은 시간부터 다시 흐른다(기존 TV·날짜 상세와 동일).

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 한 출처가 RSS 형식·주소를 바꿈 | 파싱 0건이면 `E-AND-NEWS-0003` + 그 출처만 캐시 유지. 다른 출처는 계속 동작 |
| SBS 가 전체 피드만 주도록 바뀜 | 섹션 피드 0건이면 SBS 몫만 비우고 연합뉴스로 목록을 채운다(776KB 전체 피드는 받지 않음) |
| 기사 HTML 구조 변경 | 연합 `<p>` 0개·SBS JSON-LD 없음 → RSS 요약으로 대체(오류 없음) |
| 흐르는 글자가 어지럽거나 발열 | 속도 45px/s, 30fps 상한, 패널·다른 화면에서 정지. 필요 시 15fps 상수 |
| 티커 폭 부족(알약 2개) | 420px 미만이면 숨김. 오늘 일정 알약을 우선 |
| 두 출처가 같은 사건을 다르게 씀 | 제목 중복만 합친다. 같은 사건의 다른 제목은 그대로 둔다(판단은 사람이) |
| 저작권 | 제목·요약·본문 일부를 개인용 키오스크에 표시. 출처와 시각을 항상 함께 표기, 원문 링크는 저장만 |
| 정치적 편향 | 성격이 다른 두 곳(통신사+방송사)을 섞고, 출처를 행마다 표시. 설정에서 끌 수 있음 |
