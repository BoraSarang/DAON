## [android] 0.9.0-dev — 2026-11-01 — 오늘의 뉴스 티커

### 티커 (T-052~T-056)
- 달력 상단 바의 비어 있던 가운데에 **뉴스 티커**를 넣었다. 날짜 블록과 오른쪽 버튼 사이에서 30dp/s 로 천천히 왼쪽으로 흐른다. 시각 높이 43dp·터치 48dp·본문 18sp, 좌우 23/41dp 는 표면색 그라데이션으로 가린다. 폭이 280dp 미만이면(오늘 일정·라디오 알약이 둘 다 있을 때) 숨긴다
- 움직임은 `withFrameNanos` 루프에서 **30fps 상한**을 두고 `graphicsLayer.translationX` 만 바꾼다 — 리컴포지션 0회(`CalendarHome` 재구성 12초에 5회 — 시작·날씨·뉴스 갱신분뿐). 다른 화면·설정·날짜 상세·뉴스 패널·앱 백그라운드에서는 멈춘다
- **제목 줄을 티커 높이의 세로 가운데에 맞췄다.** `Marquee` 의 `Box` 기본 정렬(Top)이라 글자가 위로 붙어 있던 것을 `CenterStart` 로 고쳤다(실기기 캡처로 확인)
- 목록이 비어 있어도 눌러서 `다시 시도` 를 할 수 있고, `뉴스` 토글을 끄면 자리도 차지하지 않는다

### 패널·기사 (T-056)
- 티커를 누르면 **화면을 벗어나지 않고** 오른쪽 600dp 패널로 목록이 열린다(20건, 행마다 `연합뉴스`/`SBS` 칩) → 기사 본문 → `‹ 이전 기사` `다음 기사 ›` `n / 20`. 뒤로가기는 기사 → 목록 → 닫기 순서로 한 단계씩 물러난다
- 연합뉴스는 `figure` 를 걷어낸 `<p>`(37문단, 1,609–2,090자), SBS 는 JSON-LD `articleBody` 를 문장 단위 문단으로(5문단, 856자) 뽑는다. 실패하면 RSS 요약만 보여 주고 그 사실을 알린다. **본문은 저장하지 않는다**
- 패널이 열려 있는 동안 자동 화면 전환이 멈춘다(`paused` 에 `newsPanelOpen` 추가). 100초 이상 열어 둬도 화면이 넘어가지 않음을 확인

### 수집·저장 (T-052~T-054)
- 출처: 연합뉴스 최신기사 RSS(`https://www.yna.co.kr/rss/news.xml`) + SBS 사회 RSS(`...SectionRssFeed.do?sectionId=03`). 두 피드 **병렬** 요청(8s connect·12s read). Google News RSS 는 기기 루트 인증서가 없어 제외
- 제목 중복만 합치고, 전적·순위·`[자막뉴스]` 는 뺀다. 출처별 10건씩 20건, 표시는 **48시간** 까지. 성공한 출처만 그 자리에서 교체하고 실패한 출처는 캐시를 그대로 둔다

- 새 오류 코드: `E-AND-NEWS-0001`(피드 실패) · `E-AND-NEWS-0002`(본문 실패) · `E-AND-NEWS-0003`(파싱 0건)

## [android] 0.8.0-dev — 2026-11-01 — 화면 테마·밝기 + 날씨 배경

### 화면 테마·밝기 (T-049)
- 설정 맨 위에 **`화면`** 섹션: `테마`(블랙/라이트) + `화면 밝기`(시스템·20·40·60·80·100%). 키오스크로 고정하면 기기 설정에 들어갈 수 없어서 앱 안에 두었다
- `Kiosk.color` 를 Compose 상태로 바꾸고 `DarkKioskColors`/`LightKioskColors` 두 벌을 둔다. 칩을 누르면 전체 화면이 그 자리에서 바뀐다. 저장값은 `App.onCreate` 에서 첫 프레임 전에 적용해 깜빡임이 없다
- 라이트 팔레트 추가(`#F4F1EA` 바탕·흰 카드·짙은 황토 강조 `#7A500F`). `onAccent`·`scrim` 토큰을 새로 두고, 강조색 바탕 위 글자(오늘 셀·선택 칩·재생 버튼)와 패널 뒤 막을 테마에 맞게 바꿨다. 대비: 본문 16.4:1 · 보조 8.4:1 · 흐린 글자 6.2:1
- **밝기**는 `WindowManager.LayoutParams.screenBrightness` 로 이 창에만 적용한다(기기 자동 밝기·잠금 화면 밝기는 그대로). `MainActivity.onCreate`·`onResume` 마다 저장값을 다시 적용한다. 실측: 20% → `sbrt=0.2`, `mScreenBrightnessOverrideFromWindowManager=51`, `시스템` → `-1`
- 테마에서 색을 잡아 두던 값(`CardSurface`, `TodayInk`, 달 글리프, 스크림)을 테마 인식으로 바꿨다. 설정·날짜 상세 패널 뒤 막도 `color.scrim` 사용

### 키오스크 고정 저장 수정 (T-047 보완)
- Fire OS 의 `화면 고정됨` 확인 창은 별도 액티비티가 아닌 SystemUI 창이라 액티비티가 `ON_RESUME` 을 받지 않는다. 그래서 `확인` 을 눌러도 토글이 꺼진 채로 남고 `kiosk_lock` 이 저장되지 않았다
- 토글을 켠 뒤 250ms 간격으로 최대 10초 `lockTaskModeState` 를 확인해 **실제로 고정된 순간** 토글·저장값을 맞춘다. 취소하면 아무 것도 저장하지 않는다. 실기기 확인: `확인` → `mLockTaskModeState=PINNED`, prefs `kiosk_lock=true`, 토글 `고정됨`, 재시작 시 자동 복원 유지

## [android] 0.6.0-dev — 2026-11-01

### 설정 저장 확정 (T-048)
- `AppPrefs` 쓰기를 `apply()` → **`commit()`** 으로 바꿨다. `apply()` 는 메모리에만 먼저 반영하고 디스크 기록을 미뤄, 설정을 바꾼 직후 앱이 내려가면(키오스크 재부팅·강제 종료) 값이 사라질 수 있었다. 실패(`false`)도 `E-AND-STORE-0001` 로 남긴다
- 자동 전환 타이머가 `라디오 화면 포함`·`TV 화면 포함` 값이 바뀌면 **즉시 다시 시작**하도록 `LaunchedEffect` 키에 넣었다(바꾼 설정이 다음 회차부터 바로 적용)
- 키오스크 토글은 **실제 `lockTaskModeState` 만 저장**한다. 시스템 확인 창에서 취소했는데 `고정됨`으로 표시되거나 다음 시작에 다시 묻는 일이 없어진다
- 실기기 확인: `라디오 화면 포함` 끔 → prefs `false` → 앱 강제 종료 후 재시작 → 설정 화면 꺼짐 유지, 화면 점 3개, `CALENDAR → WEATHER`. `이 앱에 고정` 켜면 시스템 창에서 `확인` 후 `mLockTaskModeState=PINNED`, 재시작 시 같은 창이 다시 뜬다

### 달력 (T-023·T-025·T-026)
- **T-025** 오늘 일정 요약을 달력 아래 52dp 스트립에서 **상단 바 1줄 알약**으로 옮겼다(`오늘 일정 09:30 모판 준비 1개 더`). 6주 그리드가 온전히 보이고, 알약을 누르면 오늘 날짜 상세가 열린다. 일정이 없으면 알약도 없다
- **T-026** 반복 일정 회차별 건너뛰기: `skipDates`(JSON `skipDates` 배열)에 날짜를 저장하고 펼칠 때 뺀다. 상세 패널 `이 회차만` → 같은 줄 확인(`건너뛰기`/`취소`). 시리즈와 다른 회차는 그대로
- **T-023** 공휴일 자산 갱신 가드: 시작 로그(`holiday data through …`, 만료 시 `E-AND-DATA-0002`, 60일 이내 안내) + `CalendarAssetsTest` 가 오늘·내년 공휴일이 없으면 갱신 안내와 함께 실패
- 테스트 69건(회차 건너뛰기 2건·skipDates 왕복 1건·공휴일 커버리지 1건 추가), i18n 266키

### 날씨 지점: 현재 위치 → 동네 검색 저장 (T-024)
- 지점 결정 순서: 기기 위치(프레임워크 `LocationManager`, GMS 불필요) → 설정에서 검색해 저장한 동네 → 도시 칩
- 위치 권한(`ACCESS_COARSE_LOCATION`)은 첫 실행 때 한 번만 요청. 거부·실패해도 앱은 계속 동작하고 설정에 이유와 현재 지점을 표시
- 설정 → `날씨 지점`: 동네 이름 검색(Nominatim, 1초 디바운스·초당 1회 준수), 결과 `사용`, 저장된 곳 `지우기`, `다시 찾기`
- 새 파일 `data/DeviceLocation.kt`(20초 fix 제한·24시간 캐시), `data/Place.kt`(`auto`/저장한 곳/도시), `data/PlaceSearch.kt`, `ui/PlaceLabel.kt`
- `WeatherRepository.fetch`가 도시 대신 위·경도를 받는다. 요청 URL 은 그대로 `forecast_days=7`
- 저장 값은 SharedPreferences `place_name`/`place_lat`/`place_lon`. 도시 칩을 고르면 저장한 곳은 지워진다
- 실기기 실측: 이 Fire HD 10 은 GPS 하드웨어가 없고 HERE 네트워크 위치도 좌표를 주지 않는다(`location_mode` 유지 불가, 백엔드 TLS 사설 CA 실패) → **저장한 동네가 기본**

### 일정: 로컬 저장 + 기기 캘린더 (T-003, T-004)
- 날짜 상세 패널에 `일정` 구역: 그 날의 일정 목록, 한 줄 입력 + `추가`, 로컬 일정 `×` 삭제
- 달력 셀에 일정 점(7dp) 표시, 달력 아래 `오늘 일정` 스트립(최대 2건 + `N개 더`)
- 로컬 일정은 SharedPreferences `events` + JSON 한 덩어리(`EventJson`). 일정 수가 적어 Room 없이 충분하고, 깨진 항목은 건너뛴다
- 기기 캘린더는 `CalendarContract.Instances` 로 오늘 기준 ±12개월을 읽는다(읽기 전용, 출처 `기기 캘린더 · 이름` 표시). `READ_CALENDAR` 권한은 provider 가 있는 기기에서 한 번만 요청
- Fire OS 7 에도 캘린더 provider(`com.android.providers.calendar`)가 있다. `READ_CALENDAR`를 허용하면 기기 일정을 읽고, 계정이 없으면 0건으로 표시된다(실기기 `device events=0` 확인). provider 가 없는 기기만 `UNAVAILABLE`
- 새 파일 `data/event/CalendarEvent.kt`, `EventJson.kt`, `EventStore.kt`, `DeviceCalendar.kt`. `DashboardViewModel`이 로컬+기기 일정을 합쳐 정렬
- 문자열 en/ko **190키 일치**, 테스트 4건 추가(JSON 왕복·깨진 항목·정렬) 총 **27건 통과**
- error_code: `E-AND-PERM-0002`(캘린더 읽기 실패)

### 반복 일정·음력 선택 + 화면 이동 (2026-11-01)
- 날짜 상세 패널에 **날짜 기준(양력/음력)** 과 **반복(없음·매주·매월·매년)** 칩 추가. 음력을 고르면 매년 같은 음력 날짜로 반복된다(제사·생일)
- 음력 일정은 `CalendarData.lunarDates()` 로 번들 범위(2025–2040) 안의 양력 날짜를 찾아 펼친다. 윤달도 구분해 저장한다
- 반복 일정은 원본 1건만 저장하고 화면에 그릴 때 `EventOccurrences` 가 오늘 −24개월 ~ +120개월 범위로 펼친다. 회차 사본은 시리즈 `id` 를 유지해 `×` 로 전체 삭제된다(회차별 삭제는 T-026)
- 말일 보정: 매월 31일 반복은 짧은 달에서 말일, 매년 2월 29일 반복은 평년에 2월 28일로 둔다
- 일정 행에 반복 정보 표시: `매년 음력 10월 6일`, `매주`, `매월`, `매년`
- **대시보드 카드 터치**: 시계 카드를 누르면 시계 화면, 날씨 카드를 누르면 날씨 화면으로 이동한다(자동 전환 타이머 리셋)
- **`달력` 홈 버튼**: 날씨·시계 화면 상단 바(설정 왼쪽)에 `달력` 버튼. `그 화면에서 멈추기` 모드에서도 대시보드로 돌아갈 길이 항상 보인다. 누르면 달력으로 돌아가 자동 전환이 다시 시작된다
- **기기 캘린더 판정 수정**: 권한이 있으면 provider 응답 여부로 판정한다(일정 0건이어도 사용 가능). 이전에는 `count > 0` 이라 계정 없는 기기가 `UNAVAILABLE` 로 잘못 표시됐다
- 새 파일 `data/event/EventOccurrences.kt`, 테스트 `EventOccurrencesTest`. `EventJsonTest` 3건 추가
- 문자열 en/ko **200키 일치**, 테스트 **36건 통과**(+9). 실기기에서 음력 매년 일정 추가·점 표시·카드 이동·`달력` 복귀 확인
- perf: 콜드 스타트 **1893–1894ms**(예산 2000ms), 달력 로드 238ms. error_code 영향 없음
