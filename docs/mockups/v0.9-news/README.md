# v0.9 뉴스 티커 목업

> 기준: 1920×1200 (Fire HD 10), 1dp = 1.5px · 색·활자·간격은 v0.8 토큰 그대로
> 파일: `index.html`(전체 시트) · `screens/{home,light,list,article,settings,spec}.png`
> 계획: `docs/plans/PLAN_v0.9_news.md`

## 1. 무엇을 보여 주나

달력 화면 상단, 날짜와 `라디오/TV/설정` 사이의 빈 곳에 최신 뉴스 제목이 왼쪽으로 천천히 흐른다.
누르면 오른쪽 패널에 **오늘의 뉴스 목록(연합 10 + SBS 10 = 20건)**, 목록에서 고르면 **기사 본문**이 같은 패널에서 열린다.
브라우저나 다른 앱을 열지 않으므로 화면 고정(키오스크)이 그대로 유지된다.

| 화면 | 내용 |
|---|---|
| `home` | 블랙 테마 · 티커 · 11월 달력(음력·절기·일정) |
| `light` | 라이트 테마 같은 배치 |
| `list` | 티커를 눌렀을 때 — 시간·출처 칩·제목, 아래로 이어짐 |
| `article` | 기사 본문(SBS 예시) — 제목 2줄, 본문 27px, 이전/다음 |
| `settings` | 설정 `뉴스` — 표시·1시간 간격·지금 갱신·유지 기간 안내 |
| `spec` | 치수·상태·흐름·유지 기간·출처 검증·결정 근거 |

목업의 뉴스 제목·본문은 **2026-11-01 17:5x 연합뉴스·SBS RSS 실제 값**을 옮겼다(읽기용 예시).

## 2. 왜 이렇게 정했나

| 질문 | 결정 | 근거 |
|---|---|---|
| 어디에? | 상단 바 가운데, 남는 폭 전체 | 달력 높이를 줄이지 않는다. 사용자가 지목한 자리 |
| 얼마나 크게? | 18sp / 높이 43dp / 터치 48dp | 70대 가독성 + 옆 버튼과 같은 리듬 |
| 얼마나 빠르게? | 45px/s (30dp/s) | 27px 글자가 1초에 45px. "천천히" 요구 |
| 클릭하면? | 목록 먼저, 그다음 기사 | 흐르는 제목을 정확히 집을 수 없어 **오탭을 없앤다** |
| 본문은? | 앱 안에서 추출 | WebView·브라우저 없이 키오스크 유지 |
| 몇 분마다? | **기본 1시간** (30분/1시간/3시간/6시간) + `지금 갱신` | 두 피드 합계 281KB/회 |
| 출처는? | **연합뉴스 + SBS** 한 목록에 섞기 | 한 곳이 죽어도 다른 곳은 계속 보인다 |
| 유지 기간? | **48시간**, 성공 시 즉시 교체·실패 시 유지 | 아래 §4 |
| 끊기면? | 마지막 소식 유지 + 시각만 흐리게 | 벽에 붙은 기기가 빨간 오류로 시끄러우면 안 된다 |

## 3. 출처 검증 (2026-11-01 실측)

| 후보 | 응답 | 루트 | 대상 기기(137개 CA) | 판정 |
|---|---|---|---|---|
| **연합뉴스 최신기사** | 200 · 94KB · 120건 | DigiCert Global Root G2 | 있음 | **채택** |
| **SBS 사회** `sectionId=03` | 200 · 187KB · 29건 | Amazon Root CA 1 | 있음 | **채택** |
| SBS 전체 속보 | 200 · **776KB** · 101건 | Amazon Root CA 1 | 있음 | 제외(너무 큼) |
| Google News RSS | 200 · 100KB | GTS Root R4 | **없음** | 제외 — HTTPS 실패 |
| JTBC 속보 | 200 · 1건(2024년 정지) | DigiCert Global Root G2 | 있음 | 제외 |

Fire OS 7.3.1.2(보안 패치 2018-10-05)는 시스템 CA 137개만 신뢰한다.
TBS FM 이 실패한 것과 같은 이유(새 루트 없음)로 Google News RSS 는 이 기기에서 쓸 수 없다.

SBS 는 `sectionId` 를 바꿔도 29건씩만 주고, `newsflash`·`sitemap` 은 인자를 무시하고 776KB 전체를 준다.
그래서 **사회 한 섹션만** 받는다(정치·경제·국제를 더하면 944KB/회가 된다).

### 본문 추출 — 한 곳씩 방식이 다르다
- **연합뉴스**: `<div class="story-news article">` 에서 `<figure>`(사진·기자 사진)를 먼저 지우고 `<p>` 만 모은다. 실측 17문단.
- **SBS**: JSON-LD `@graph[0].articleBody` 한 덩어리(실측 955자). 문장 끝에서 끊어 문단으로 나누고,
  `▲ …` 사진 설명 줄은 뺀다.
- 둘 다 실패하면 RSS `description` 으로 조용히 대체한다.

## 4. 유지 기간 — 질문에 대한 답

| 상황 | 동작 |
|---|---|
| 새 목록을 받음 | 그 출처 몫을 **즉시 교체**. 피드에서 빠진 기사는 바로 사라진다 |
| 한 출처만 실패 | 성공한 쪽만 교체, 실패한 쪽은 **마지막 목록 유지** |
| 둘 다 실패 | 아무것도 지우지 않는다 |
| 48시간 지남 | 표시에서 빠지고 다음 저장 때 파일에서도 지운다 |
| 앱 재시작 | prefs 에서 읽어 즉시 표시(48시간 이내 것만) |
| 기사 본문 | **저장하지 않는다.** 열 때 1회 받고 패널을 닫으면 버린다 |

- "하루 지나면 폐기"가 아니라 **48시간**이다. 밤사이 갱신이 한두 번 실패해도 아침에 빈 화면이 되지 않게 하는 여유.
- 저장은 출처별 30건(표시는 20건)이라 잠깐 밀려도 목록이 비지 않는다. JSON 25~35KB.
- 즉시 교체이므로 **"갱신 = 이전 것 폐기"가 맞다.** 단 실패했을 때는 폐기하지 않는다.

## 5. 구현 메모

- **티커**: `withFrameNanos` + `graphicsLayer.translationX` (리컴포지션 없음), 33ms 이상일 때만 이동(30fps 상한).
  정지: 달력 화면 아님 · 뉴스/설정/날짜 패널 열림 · 앱 백그라운드 · 폭 420px 미만.
- **기존 "달력 유휴 0프레임" 지표는 "30fps(티커)"로 바뀐다.** 상시 켜짐 기기라 30fps 상한을 상수로 두고
  실측 후 필요하면 15fps 로 낮춘다.
- **목록·기사**: 600dp 오른쪽 패널 하나에 두 상태. `paused` 조건에 `newsPanelOpen` 추가.
- **요청**: 두 피드를 병렬로(HttpURLConnection 2개). 직렬이면 대기 시간이 2배가 된다.
- **저장**: `news_items`(출처별 30건 JSON) + 출처별 `news_updated_at`. 첫 프레임 뒤 읽고, 네트워크는 그 뒤에.
- **오류 코드**: `E-AND-NEWS-0001`(피드·요청), `0002`(기사 요청), `0003`(형식).

## 6. 다시 렌더하기

```bash
cd docs/mockups/v0.9-news
CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
for v in home light list article settings spec; do
  "$CH" --headless=new --disable-gpu --hide-scrollbars \
    --force-device-scale-factor=1 --window-size=1920,1200 --virtual-time-budget=2500 \
    --screenshot="screens/$v.png" "file://$PWD/index.html?shot=$v"
done
```

`index.html` 을 브라우저로 열면 여섯 장면을 캡션과 함께 볼 수 있다.
`?shot=home` 처럼 열면 한 장면만 1920×1200 으로 렌더된다.

## 7. 남은 확인

1. 티커를 눌렀을 때 **목록 먼저** — 확정.
2. 기사 패널 폭 600dp·본문 27px — 확정("적당해").
3. 출처 연합뉴스 + SBS — 확정.
4. 기본 1시간 + `지금 갱신` — 확정. 실기기에서 1시간 주기 CPU·발열을 재고 필요하면 3시간을 권한다.
